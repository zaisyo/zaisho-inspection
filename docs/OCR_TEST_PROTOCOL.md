# OCR 評価手順・データ取扱い

## 正解データセット
- ラベル: メーカーごと、文字サイズ/角度/反射/距離/縦横の異なる画像を用意する。各画像に ground_truth（品番、管理番号、入数）を手入力。
- 納品書: レイアウトの異なる納品書を収集。表の行単位で品番と数量の正解を作る。
- 顧客名/住所/電話番号/担当者名は共有・アップロード前に伏せる。原本は社内管理。
- GitHub 公開リポジトリには業務納品書・個人情報・原画像をコミットしない。
- テスト画像は権利・共有許可を確認した匿名化画像のみを使用。

## 1件あたり記録する項目
test_id, device, browser, image_width, image_height, crop(x,y,w,h), preprocess_type, warm_start, worker_init_ms, image_decode_ms, preprocess_ms, recognize_ms, parse_ms, total_ms, raw_text, recognized_part, expected_part, accepted_auto, reviewed, failure_reason。

## 定量評価
- 品番完全一致率 = exact match数 / 評価件数
- 誤確定数 = 人手確認なしに誤品番を採用した件数（合格値: 0）
- 操作時間 = 撮影開始から確認までの実測時間。中央値とP95を両方算出する。
- エラーを「撮影品質」「切出し」「前処理」「認識」「抽出」「照合」「操作」に分類する。
- 訓練/調整用画像と最終判定用画像をメーカーまたは撮影ロット単位で分離し、同じ画像での過適合を防止する。

## 初回テスト手順
1. 同じ画像の原画像OCRと現行crop OCRを比較する。
2. OCR文字が読める大きさかを画像として保存し、切り出し座標を可視化する。
3. 補正なし、グレースケール、コントラスト、二値化の結果を画像付きで比較する。
4. 各パターンの文字列・時間を計測し、条件別に統計をとる。
5. 「-5」など不正候補は非確定として扱い、その画像の切り出し範囲を確認する。

## 合否の確認
精度の根拠となるテスト件数と実行環境が不足する段階では「未測定」とする。開発中の目標値を実績値として表示しない。
